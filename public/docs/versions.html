Versions and changes

Load the version line that suits you. A line gets fixes but never changes in a way that breaks your site.

Which URL to load

URLWhat you get
https://wallet.selfhold.app/v1/selfhold.jsThe latest release of version 1. It updates in place with fixes and new options, never with a change that breaks a site. Most sites should load this.
https://wallet.selfhold.app/v1.0.0/selfhold.jsOne release, exactly. It never changes. Pin it with its integrity hash, so the browser refuses anything else.
 
<script type="importmap">
{
  "integrity": {
    "https://wallet.selfhold.app/v1.0.0/selfhold.js": "sha384-qEys5mx9ezZB7J+IqJrPZlUcGNxZYrHkkADOaYB94L9EanvlwH/uBi+nWMYNN+Ra"
  }
}
</script>
<script type="module">
  import { selfhold } from "https://wallet.selfhold.app/v1.0.0/selfhold.js";
</script>

The import map's integrity makes the browser refuse the script unless it is exactly that release. Each release's hash is published beside it, at /v1.0.0/integrity.txt. You can also copy the file into your site.

A change that would break a site gets a new line, /v2/, and /v1/ keeps working. Selfhold's window keeps answering older versions of the library.

Changes

1.0.0 2026-10-29

  • One wallet object for Selfhold for Chrome and Selfhold's window.
  • writeRecords() resolves with a Sent you can wait() on: sent, slow, late, then landed, or Lost or NotRecorded.
  • Every failure is a SelfholdError with a code, a message for the person and a docUrl.
  • Selfhold's window takes calls from sites on localhost.

Before 1.0.0, https://wallet.selfhold.app/selfhold.js served the window-only library. It still does, unchanged in behaviour, for sites that load it.
